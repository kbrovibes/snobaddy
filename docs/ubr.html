1. Philosophy

Snobaddy UBR is a modified Elo system tuned for recreational doubles badminton. It draws from the real UBR system, Glicko-1, and UTR (Universal Tennis Rating).

Core principle: Your rating reflects how you perform relative to expectations, not just whether you win or lose. A close loss to a much stronger team can raise your rating. A narrow win over a much weaker team can lower it.

Design goals

  • Works across all 3 snobaddy scoring modes (full, simple, whiteboard)
  • Handles drop-in play — irregular attendance, varying opponents
  • Converges quickly for new players, stabilizes for veterans
  • Transparent — players can understand why their rating changed

New players also start with Rating Deviation (RD) = 350 — the system is very uncertain about their true strength until they play enough matches.

4. Scoring Modes & Data Quality

Snobaddy supports 3 scoring modes. Each provides different data, so the algorithm treats them differently:

Full Mode
4 player IDs + exact scores
High quality

Score margin adjusts impact. Best rating signal.

Simple Mode
4 player IDs + win/loss only
Medium quality

No score margin. Uses neutral multiplier (0.5).

Whiteboard
Per-player W/L totals only
Lower quality

No opponent info. 25% discount applied.

5. Core Formula (Match-Based)

For sessions with explicit match records (full & simple modes), we use doubles Elo.

Step 1: Team Ratings

R_team = (R_player1 + R_player2) / 2

Step 2: Expected Outcome

// Logistic curve — probability Team 1 wins E = 1 / (1 + 10 ^ ((R_opponent - R_team) / 400))

If teams are equally rated, E = 0.5 (50/50). A 400-point gap gives the stronger team ~91% expected win rate.

Step 3: Score Margin (Full Mode Only)

margin_mult = log2(1 + score_diff) / log2(22)
ScoreMarginMultiplier
21–1920.33 (close)
21–1560.59 (normal)
21–10110.75 (dominant)
21–0210.96 (blowout)

Simple mode uses a fixed 0.5 (neutral — roughly equivalent to 21–15).

Step 4: K-Factor

Controls how much one match can move a rating. Higher for new players, lower for veterans.

Match CountK BasePhase
< 1548Provisional (rating moves fast)
15 – 3936Establishing (settling in)
40+24Established (stable)

K is further adjusted by Rating Deviation: K = K_base × (1 + (RD - 50) / 600)

Step 5: Rating Change

// S = 1.0 (win) or 0.0 (loss) ΔR = K × (S - E) × (0.5 + margin_mult) // Final: floor at 1000 R_new = max(1000, R_old + ΔR)
What this means:
  • Upset win (you beat a stronger team) → big gain
  • Expected win (you beat a weaker team) → small gain
  • Close loss to stronger team → minimal loss
  • Blowout loss to weaker team → significant loss

6. Tally Sessions (Whiteboard)

Whiteboard sessions only record per-player win/loss totals — no opponent info. We use the Session Pool Method.

Why discount tally data? Going 5–3 against top players is very different from 5–3 against beginners. Without opponent info, we apply a 25% quality discount and cap the effective match count.
// Pool = average rating of all session participants R_pool = average(all participant ratings) // Expected win rate against the pool E = 1 / (1 + 10 ^ ((R_pool - R_player) / 400)) // Actual win rate S = wins / (wins + losses) // Effective matches (capped at 8) eff = min(floor((wins + losses) / 2), 8) // Rating change (with 0.75 tally discount) ΔR = K × 0.75 × eff × (S - E)

7. Confidence & Decay

Rating Deviation (RD) tracks how confident the system is in a player's rating. Borrowed from the Glicko system.

RD RangeConfidenceMeaning
50 – 100HighActive player, rating is reliable
101 – 200MediumSemi-active, some uncertainty
201 – 350Low (Provisional)New or inactive — rating will swing more

Inactivity decay

Each session a player misses, their RD grows slightly:

RD_new = min(350, sqrt(RD² + 15²))

This means an inactive player's next result will have more impact — the system acknowledges it doesn't know their current level.

Active play

Each match played decreases RD. Active players converge toward RD = 50 (high confidence).

8. Processing Flow

UBR updates are triggered when a non-test session is finalized.

Session finalized
→
Skip if test session
→
Decay RD for absent players
→
Process matches or tally
→
Update RD for participants
→
Cache to ubr_ratings
→
Write ubr_history
Full recalculation: Ratings can be rebuilt from scratch by replaying all finalized non-test sessions in date order. This ensures the system is always auditable and reproducible.
