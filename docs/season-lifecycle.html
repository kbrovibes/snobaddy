Season Lifecycle Management

Create, activate, close, and browse seasons in Snobaddy. God Mode only.

Spec 34

Overview

Snobaddy runs in seasons — Spring, Summer, Fall, Winter — each spanning roughly 3 months. Today, the season is a static DB row. This spec adds a full lifecycle: create upcoming seasons, activate them, close completed ones, and reopen if needed.

Key Principle
At most one season can be active at a time. Sessions, finals, and the leaderboard all scope to the active season. When a season closes, a new one can begin.
UBR Ratings Are Cross-Season
The UBR (Universal Badminton Rating) system does not reset per season. Ratings accumulate across all time. Only the leaderboard (W/L stats) resets with each season.

Season States

Each season moves through three states:

Upcoming
Created, waiting
→
Active
Sessions run here
→
Completed
Read-only archive
TransitionGuardWhat Happens
Create None New season saved as upcoming (or active if none exists)
Start No other active season Status flips to active; sessions can now be created under it
Close No active sessions Status set to completed; stats frozen; leaderboard archived
Reopen No other active season Status reverts to active; sessions and leaderboard resume

Database Changes

Migration: Add status to seasons
ALTER TABLE seasons
  ADD COLUMN status TEXT NOT NULL DEFAULT 'active'
  CHECK (status IN ('active', 'upcoming', 'completed'));

-- Enforce at most one active season
CREATE UNIQUE INDEX idx_seasons_one_active
  ON seasons ((1)) WHERE status = 'active';

The existing Spring 2026 row is set to active. The unique partial index guarantees only one season can be active at any time.

Edge Cases

ScenarioBehavior
No active season, user hits / "No active season" message + link to Seasons page (god mode) or generic message (others)
Admin creates session with no active season API returns 400: "No active season. Start a season first."
Admin tries to close season with active sessions Blocked: "Close all active sessions first"
Admin tries to start season while another is active Button disabled; tooltip: "Close the current season first"
Season with no sessions (freshly created) Stats cards hidden (existing daysOfPlay > 0 check)
Reopen a completed season Allowed if no other season is active; reverts to active

Acceptance Criteria

  • seasons table has status column: active, upcoming, completed
  • At most one season can be active at any time (DB constraint)
  • God mode users see a "Seasons" tab in bottom nav
  • Seasons page lists all seasons with status badges and stats
  • Admin can create a new season with name + dates
  • Admin can close the active season (if no active sessions)
  • Admin can start an upcoming season (if no other is active)
  • Admin can reopen a completed season (if no other is active)
  • Home page only shows sessions from the active season
  • Leaderboard only shows stats from the active season
  • Session creation fails gracefully when no season is active
  • Finals creation uses the active season, not most-recent-by-date
  • UBR ratings remain unchanged (all-time, cross-season)
  • Regular (non-god-mode) users see no changes in their experience
