# Release v0.10.0 — Match Generation Algorithm

## Overview
This is a major feature update that introduces an automated match suggester to solve the club's "Who plays next?" problem. It uses a persistent queue of up to 4 suggested matches, calculated using a weighted heuristic algorithm.

## Changes

### 1. The Propose Algorithm (`src/lib/db/proposed.ts`)
- **Weighted Scoring:** Evaluates all valid player combinations based on:
    - **Anti-Back-to-Back (-2000 per player):** Heavy penalty for players in the most recent match.
    - **Team Balance (-100 per skill diff):** Minimizes the gap between Team A and B combined skills.
    - **Sanity Check (-1000):** Actively blocks "dumb" lineups where a single player is significantly outclassed (e.g., 5,5,5,1).
    - **Diversity Bonus:** Rewards pairings that haven't occurred yet in the current session.
    - **Phase logic:** Shifts from "Mixing" (pairing high with low) to "Convergence" (pairing similar skills) as the session progresses.

### 2. Database Schema
- New table `proposed_matches` stores the temporary queue.
- Linked to `sessions` and `players` with cascade deletes.

### 3. Proposed Match Queue UI
- New component `ProposedMatchList.tsx` displays up to 4 cards.
- **Fill Delta:** Only generates the number of matches needed to reach the queue limit.
- **Delete:** Individual suggestions can be removed without affecting others.
- **Record Score:** Opens the match form pre-filled with the 4 players. Saving the score automatically removes the proposal from the queue.

### 4. RecordMatchForm Integration
- Updated `RecordMatchForm.tsx` to handle pre-fill data.
- Manual entry is still fully supported via the primary action button.

## Technical Notes
- **Greedy Optimization:** To prevent O(N^4) complexity with 50+ players, the algorithm anchors on the "most rested" player first and then searches for optimal teammates/opponents.
- **Persistence:** Recommendations are stored in the DB, allowing all players (not just the generator) to see the proposed lineup in real-time.
