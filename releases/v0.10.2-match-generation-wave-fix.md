# v0.10.2 — Match Generation Wave Fix

## Summary
Fixed a logic flaw in match generation that capped suggestions at 3 even when 4 were expected. Renamed two UI labels for clarity.

## Root Cause
`proposeNextMatches` locked players cumulatively across all 4 proposed slots. With 12 players: wave 1 consumed 4+4 = 8, wave 2 found only 4 available → filled match 3, then 0 left → broke out before match 4. The algorithm did not model the 2-court constraint (only 2 matches run simultaneously).

## Fix: Wave-Based Locking (`src/lib/db/proposed.ts`)
- Introduced `COURTS = 2` constant — matches per simultaneous wave.
- Players are now locked only within the current wave (2 slots). At the start of each new wave, `waveLocked` is cleared and all checked-in players are eligible again.
- Handles partial-wave deltas correctly: seeds `waveLocked` from the tail of existing proposals that are in the same wave before filling.

### Example with 12 players, 0 existing proposals
| Slot | Wave | Available | Action |
|------|------|-----------|--------|
| 0    | 1    | 12        | Pick match 1, lock 4 |
| 1    | 1    | 8         | Pick match 2, lock 4 |
| 2    | 2    | 12 (reset)| Pick match 3, lock 4 |
| 3    | 2    | 8         | Pick match 4, lock 4 |

## UI Changes (`src/components/ProposedMatchList.tsx`)
- Empty state button: "🏸 Suggest Matches" → "✨ Generate Matches"
- Top-up button: "+ Fill Delta" → "+ Add Matches"
- Loading label: "Suggesting..." → "Generating..."
