# v0.39.4 — Newsletter Banner Restyle + Regenerate UI Removal

Date: 2026-05-15

## What changed

### 1. Session-list newsletter link, on-theme
The old banner used `bg-sky-50/60` over `border-sky-200` with a single small uppercase label. It didn't look like the rest of the app — surface cards, stone-900/sky-600 primary discs, the same idiom the session rows themselves use.

Replaced with a real card:
- `rounded-xl bg-surface shadow-sm` container with hover/active states matching session rows
- 40px circular icon disc in `bg-stone-900 dark:bg-sky-600` (the app's primary CTA color)
- Title (`text-sm font-semibold text-heading`) plus subtitle ("Stats, awards, and observations from this season") for the heading hierarchy
- Right-side chevron, same color and weight as session-row chevrons

Visually consistent with `SessionRow`, `SeasonCard`, and the rest of the app shell.

### 2. Regenerate UI removed
The in-app regenerate flow is gone:
- `src/components/RegenerateNewsletterForm.tsx` — deleted
- `src/app/api/admin/seasons/[id]/newsletter/route.ts` — deleted
- The empty god-mode-only path on the viewer page is gone

Regeneration is now CLI-only via:
```
set -a && source .env.local && set +a && \
npx tsx scripts/seed-newsletter.mts <seasonId>
```

The first-visit auto-generate on the viewer page is unchanged — if the row is missing, it generates and persists.

### 3. Generated-at, no version
Header on the viewer page used to read `v4 · May 15, 6:03 PM`. Now it reads `Generated May 15, 2026, 6:03 PM`. The `version` column still exists in the DB and still increments on update via the trigger; it's just not surfaced.
