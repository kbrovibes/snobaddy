# v0.39.5 — Newsletter Lock-Date Gating + Generate Button + Spec Doc

Date: 2026-05-15

## Three things in this release

### 1. Newsletter visibility now follows the stats lock date
The newsletter shouldn't exist before a season is "closed for the books". Visibility is now:
- Lock date **not set** → nothing
- Lock date **set, still in the future** → nothing (no link, no button)
- Lock date **set, in the past, no newsletter row yet** → "Generate newsletter" button on the SeasonCard
- Lock date **set, in the past, newsletter row exists** → newsletter link on the SeasonCard + the banner on the session list

The session-list banner only renders once a newsletter has been generated; it no longer surfaces "hey go generate this" — that affordance lives on the admin Seasons page where it belongs.

### 2. "Generate newsletter" button
- Component: `src/components/GenerateNewsletterButton.tsx` (client; primary CTA styling — `bg-stone-900 dark:bg-sky-600`)
- Endpoint: `POST /api/admin/seasons/[id]/newsletter/generate`
- Server validates: season exists, has a `stats_lock_date`, that date is `<= today`, and no `season_newsletters` row exists yet. Returns 400/409 with a readable error otherwise
- On success, generates the snapshot + markdown via the same `getSeasonStats` + `generateNewsletter` pipeline used everywhere else, persists via `upsertNewsletter`, and the client calls `router.refresh()` — the page comes back with the button replaced by the newsletter link

This is the **only** in-app way to create a newsletter. There is no in-app regeneration. To re-run, use:
```
set -a && source .env.local && set +a && \
npx tsx scripts/seed-newsletter.mts <seasonId>
```

### 3. Spec doc
`docs/newsletter-spec.md` captures the **intent** behind the newsletter — section structure, voice rules, leaderboard alignment, awards eligibility, the Sekhar self-recusal mechanism, and the three generation paths. The spec is the source of truth; the generator code implements it. Future generator changes should update the spec first so we don't lose context across sessions.

### Bonus tweaks
- **SVG icon** replaces the 📰 emoji in the session-list banner. Rolled-newspaper outline in white on the existing primary disc — renders identically across platforms.
- **"Generated" wording removed** from the newsletter UI. The viewer page header now reads "As of &lt;date&gt;"; the in-body footer line uses "Compiled" instead. The word stays in API/URL semantics where it's a verb describing the action, not user-facing copy.
- The user's own data model is unchanged. `season_newsletters.version` still exists and still increments on update via the trigger — it's just not surfaced.
