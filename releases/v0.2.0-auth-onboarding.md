# v0.2.0 — Auth & Onboarding

**Released:** 2026-03-30
**Type:** Feature

## What changed

All routes now require a Google login. First-time users are prompted to self-rate their badminton skill (1–5). A player record is created automatically on first login.

## Technical detail

### Auth flow
- Google OAuth via Supabase Auth (configured in Supabase dashboard → Authentication → Providers)
- `src/middleware.ts` guards all routes except `/login` and `/auth/*`
- `src/app/auth/callback/route.ts` exchanges OAuth code for session, creates player record on first login
- Admin emails auto-granted `is_admin = true` on first sign-in (whitelist in `src/lib/db/players.ts`)

### Three Supabase clients
| File | Key used | Purpose |
|------|----------|---------|
| `src/lib/supabase.ts` | Service role | Privileged DB queries |
| `src/lib/supabase-server.ts` | Anon + cookies | Server-side session checks |
| `src/lib/supabase-browser.ts` | Anon | Browser-side OAuth trigger |

### Database
`players` table created:
- `user_id uuid references auth.users(id)` — nullable (to support manually-added players)
- `skill_level int default 3` — set during onboarding, admin-editable later
- `is_admin bool default false`
- `onboarding_complete bool default false`

### Pages
- `/login` — Google sign-in button with logo
- `/onboarding` — skill level picker (1 Beginner → 5 Pro), skip defaults to 3
- App shell: `(app)/layout.tsx` with fixed header (logo + logout avatar) and bottom nav

## Environment variables introduced

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_SUPABASE_URL` | Public project URL (browser auth) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Anon JWT key (browser auth) |

## Supabase dashboard setup required

- Authentication → Providers → Google → enable, paste Client ID + Secret
- Authentication → URL Configuration → add redirect URLs for prod and localhost
