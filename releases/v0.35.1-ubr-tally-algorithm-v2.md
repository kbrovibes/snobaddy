# v0.35.1 — UBR Tally Algorithm v2 (Doubles-Dampened)

## Summary
Rewrote the tally-session UBR rating algorithm. The old algorithm used raw Elo expected outcomes which penalized high-rated players in doubles (going 9-2 could DROP your rating). The new algorithm uses doubles-dampened expectations that correctly reflect random-partner dynamics.

## Root Cause
`processTallySession` compared `actualWinRate` against `expectedOutcome(playerRating, poolRating)`. For a player rated 5500 in a 4000-average pool, Elo expects ~99.8% win rate. So an 82% win rate (9-2) appeared as *underperformance*, producing a negative delta.

This is wrong for doubles: with random partners, individual rating advantage is heavily dampened. An 80%+ win rate in a mixed pool is exceptional regardless of rating.

## Changes

### Constants (`src/lib/db/ubr.ts`)
| Constant | Old | New | Why |
|---|---|---|---|
| `TALLY_DISCOUNT` → `TALLY_K_WEIGHT` | 0.75 | 0.85 | Tally is now primary mode; less discount needed |
| `TALLY_MAX_EFFECTIVE` | 8 | 10 | Allow more match credit per session |
| `TALLY_MATCH_CREDIT` | 0.50 (floor(n/2)) | 0.75 (ceil(n*0.75)) | More credit for games played |
| `DOUBLES_DAMPING` | — | 0.25 | New: compresses Elo expected toward 0.5 |
| `PERFORMANCE_BONUS_THRESHOLD` | — | 0.05 | New: activates bonus above session avg +5% |
| `PERFORMANCE_BONUS_SCALE` | — | 0.3 | New: bonus multiplier |

### Algorithm (`processTallySession`)
1. **Doubles-dampened expected**: `E_doubles = clamp(0.5 + (E_elo - 0.5) * 0.25, 0.3, 0.7)` — keeps expected win rate in a realistic range for doubles
2. **Performance bonus**: Players outperforming session average by >5% get a small bonus
3. **Volume scaling**: 75% of games → effective matches (was 50%), capped at 10 (was 8)
4. **Delta**: `K_tally * effectiveMatches * (winRate - doublesExpected + performanceBonus)`

### Worked example (9-2 in 4000-rated pool, player at 5500)
- Old: E=0.9998, delta = -16 (DROPS)
- New: E_doubles=0.625, delta = +50 (RISES)
