# v0.22.1 — Tally Photo Import: improved prompt + red unmatched UX

## Summary
Upgraded the AI extraction prompt to use tally-mark-specific counting rules
(from prior Claude research). Changed unmatched player UX from amber to red
with a blocking save guard. Added wins≠losses balance check.

## Key changes

### Prompt (extract route)
- Replaced generic vision prompt with a validated tally-mark-aware prompt
- Teaches the model: crossed group = exactly 5, diagonal is the 5th stroke not an extra
- Handles leaning/overlapping strokes, two-column board layout (left + right halves)
- AI now returns raw names only — roster sent to AI removed entirely
- Server does fuzzy name matching after extraction (cleaner separation of concerns)

### Server-side name matching (`matchName`)
1. Exact full-name match (case-insensitive)
2. Known first-name defaults: Kiran→Iyer, Swathi→Rajan, Teja→Boppana
3. Unambiguous first-name match (single player with that first name)
4. Substring match (e.g. "SaiDurga" → "Sai Durga")
5. → null (unmatched) if nothing fits

### Response shape
Now includes `raw_name` (name as on board), `unmatched` flag, and `validation`
object `{ balanced, total_wins, total_losses }`.

### UI (TallyEntryForm)
- Unmatched rows: **red** background + red border (was amber)
- Dropdown placeholder shows `✕ "BoardName" — not in system`
- Red banner: "Cannot save yet. Resolve or delete red rows."
- Yellow banner: wins≠losses imbalance warning (non-blocking, recomputed live)
- Save button disabled until all red rows resolved or deleted
