# v0.23.0 — God Mode: Reset Session (Spec 15)

## What shipped
⚡ Reset Session button on active session pages, visible only to God Mode users. Permanently deletes all match records and proposed matches for the session with a confirmation dialog showing live counts.

## Files created/modified
| File | Action |
|------|--------|
| `src/app/api/sessions/[id]/reset/route.ts` | Created — GET (pre-flight counts) + POST (hard delete); God Mode guard on both |
| `src/components/ResetSessionButton.tsx` | Created — fetches counts, shows confirmation dialog, calls POST, refreshes page |
| `src/app/(app)/session/[id]/page.tsx` | Renders `<ResetSessionButton>` above `<CloseSessionButton>`, god mode only |

## Flow
1. God Mode user taps ⚡ Reset Session
2. GET `/api/sessions/[id]/reset` → returns `{ matches, proposed }`
3. Confirmation dialog: "This will permanently delete: X recorded matches, Y proposed matches. Check-ins will not be affected. This cannot be undone."
4. Cancel → dialog closes, nothing changes
5. Confirm → POST `/api/sessions/[id]/reset` hard-deletes both tables for the session → `router.refresh()`

## Auth
- Both GET and POST check `is_god_mode = true` on the player row; non-god-mode requests get 403
- Uses service role client for deletes (bypasses RLS)

## Notes
- Session status, check-ins, and player data are untouched
- `is_god_mode` column was already in place from prior work
