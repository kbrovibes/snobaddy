# v0.37.0 — Faster Tab Switching (Performance)

## Summary
Parallelized DB queries, fixed N+1 patterns, added skeleton loading states, and deduplicated auth checks to make bottom nav tab switching significantly faster.

## Changes

### T1: Parallelize Session page queries
- **File:** `src/app/(app)/page.tsx`
- Batched `getActiveSession()`, `getActiveSeason()`, and `supabase.auth.getUser()` into a single `Promise.all`
- Parallelized `getSeasonStats()` and `getFinalsSessionPair()` (previously sequential)
- Reduces session page waterfall from 4 sequential stages to 2

### T2: Fix Seasons N+1 query
- **File:** `src/lib/db/seasons.ts`
- Replaced sequential for-loop in `getAllSeasons()` (4 queries × N seasons) with 4 parallel bulk queries
- Session counts, match counts, player counts, and finals statuses all fetched in one pass
- ~650ms → ~40ms estimated improvement

### T3: Loading skeletons
- **Files:** `src/app/(app)/loading.tsx`, `players/loading.tsx`, `leaderboard/loading.tsx`, `admin/seasons/loading.tsx`
- Added `loading.tsx` skeleton files for all 4 tab routes
- Users see animated placeholder UI instantly during navigation instead of a blank screen

### T4: Deduplicate auth checks
- **File:** `src/lib/auth.ts` (new), `layout.tsx`, `page.tsx`, `players/page.tsx`, `leaderboard/page.tsx`, `admin/seasons/page.tsx`
- Created `getAuthPlayer()` using `React.cache()` — one DB round-trip per request even when called from multiple server components
- Removed redundant `supabase.auth.getUser()` + `players.select("is_admin")` from each page
- Saves ~60ms per page load (2 fewer DB queries)

## Migration
No DB changes required.
