# v0.16.0 — Email Sign-up Onboarding Fix

## Problem

Email users who logged in via `signInWithPassword` without clicking their
confirmation link entered the app with no player record. The app layout only
checked `user` (auth), not whether a player record existed. Result: invisible
in player list, check-in silently failed, no onboarding prompt.

Even for users who did click the confirmation link, a "Skip for now" escape
hatch on the onboarding page set `onboarding_complete: true` with skill 3
without the user making an active choice.

## Changes

### `src/app/(app)/layout.tsx`

- Fetch `onboarding_complete` alongside `id` on the player query
- If no player record exists: create a stub via service role (skill 2,
  `onboarding_complete: false`) so the user has a row to update in onboarding
- Hard redirect to `/onboarding` if `onboarding_complete` is false
- `playerId` prop to `<Header>` is now non-nullable (guaranteed by the gate)

### `src/app/onboarding/page.tsx`

- Removed `skip()` function and "Skip for now" button
- Replaced skip button with a note: "You can update this anytime from the
  Players page."
- Save & Continue still requires an active selection (unchanged)

## Default skill level

Stubs created in the layout default to `skill_level: 2` (Casual). This is
intentionally conservative — it's better to underrate a new player than to
throw them into advanced matches.

## Flow after fix

```
Email user signs in (any path)
        │
        ▼
(app)/layout.tsx
  ├── No player record? → INSERT stub (skill 2, onboarding_complete: false)
  └── onboarding_complete: false? → redirect /onboarding
        │
        ▼
/onboarding — must pick skill 1–5, no skip
        │
        ▼
UPDATE players SET skill_level = N, onboarding_complete = true
        │
        ▼
/ (home) — player visible, check-in works
```
