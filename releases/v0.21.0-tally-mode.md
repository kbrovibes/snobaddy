# Release v0.21.0 — Tally Mode

**Date:** 2026-04-05
**Spec:** [specs/23-tally-mode.md](../specs/23-tally-mode.md)

## Summary

Admins can enter W/L tallies for sessions where individual matches were not recorded — historical sessions that predate the app, or future sessions where the whiteboard was used instead. Tally data lives in a new `session_tally` table, completely separate from `matches`. Stats roll up into the season leaderboard.

---

## DB Migration

Run in Supabase SQL editor **before deploying**:

```sql
CREATE TABLE session_tally (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id  uuid NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  player_id   uuid NOT NULL REFERENCES players(id),
  wins        integer NOT NULL DEFAULT 0,
  losses      integer NOT NULL DEFAULT 0,
  created_at  timestamptz DEFAULT now(),
  UNIQUE (session_id, player_id)
);
```

No changes to existing tables.

## Architecture Notes

- **Mutual exclusivity**: `session_tally` and `matches` are never both populated for the same session. The tally API rejects if matches exist; the match API rejects if tally rows exist. Enforced in code, not by DB constraint.
- **Full replacement on save**: `upsertSessionTally()` deletes all existing rows for the session then re-inserts. This handles row removal cleanly when the admin removes a player before re-saving.
- **Leaderboard**: `getActivePlayers()` adds a fourth parallel fetch of `session_tally`. After the match aggregation loop, tally W/L/played are added into the same in-memory statsMap. No season filtering — consistent with existing all-time leaderboard behavior.
- **Tally sessions are skipped for session highlights** — highlights require match-level data (scores, player pairings). Sessions with only tally data will have `highlights.totalMatches === 0`, which already gates the SessionHighlights render.

## Testing Checklist

### Pre-deploy (required)
- [ ] Run the `CREATE TABLE session_tally` migration in Supabase SQL editor
- [ ] Verify the table exists: `SELECT * FROM session_tally LIMIT 1;` should return empty, not error

### Admin: initial tally entry
1. Navigate to any **completed** session that has **no recorded matches**
2. Confirm "Enter Final Scores" button appears (dashed border button)
3. Click it — form should expand inline
4. Add 3–4 players via the dropdown; confirm each added player disappears from the dropdown
5. Enter W and L values for each player
6. Confirm "Save Tallies" is disabled until all rows have both W and L filled
7. Save — page should refresh and show the tally scoreboard
8. Confirm "Final Scores · Tally-only" heading appears
9. Confirm players are sorted: most wins first, then fewest losses
10. Confirm Win% is calculated correctly

### Admin: edit existing tallies
1. On a session that already has tally data, confirm "Edit Tallies" link appears below the scoreboard (admin only)
2. Click "Edit Tallies" — form opens pre-filled with existing values
3. Change a player's W/L count and save — scoreboard should update
4. Open edit again, remove a player, save — that player should disappear from the scoreboard
5. Click "Cancel" — form closes, no changes persisted

### Non-admin: view only
1. Log in as a non-admin player
2. Navigate to a tally session — confirm tally scoreboard is visible
3. Confirm no "Enter Final Scores" or "Edit Tallies" buttons appear

### Leaderboard integration
1. After saving tally data for a session, navigate to the season leaderboard
2. Confirm the tallied players' W/L counts have increased by the correct amount
3. Confirm players who only appear in tally sessions (never recorded a match) show up on the leaderboard with their tally totals

### Mutual exclusivity guards
1. **Tally blocked by matches**: Open a completed session that HAS recorded matches — confirm the "Enter Final Scores" button is NOT shown
2. **Match blocked by tally**: Using browser devtools or curl, POST to `/api/matches` for a session that has tally data — confirm 409 response with `"Cannot record matches: tally data already exists for this session"`
3. **Tally blocked by matches (API)**: POST to `/api/sessions/{id}/tally` for a session that has recorded matches — confirm 409 response

### Active sessions
1. Navigate to an **active** session — confirm no tally UI appears (tally is completed-only)

### Edge cases
1. Save tally with only 1 player — should work fine
2. Save tally with wins=0, losses=0 for a player — should save and show 0% win rate
3. Try saving with a negative number (manually edit input) — API should return 400
