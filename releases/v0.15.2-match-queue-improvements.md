# v0.15.2 — Match Queue Improvements

**Spec:** [specs/12-match-queue-improvements.md](../specs/12-match-queue-improvements.md)

## Changes

### Team balancing (`src/lib/db/proposed.ts`)
Added `balanceTeams(players)` helper. After `findBestMatch` selects a group of 4 players, all 3 possible 2v2 splits are enumerated and the most skill-balanced split is chosen. Tiebreak: minimise intra-team skill gap (`|A1-A2| + |B1-B2|`). Team assignments stored in `proposed_matches` and `workingHistory` reflect the balanced split.

### Dynamic queue cap (`src/lib/db/proposed.ts`)
Added `getQueueCap(checkedInCount)`:
- < 8 players → 0 (no auto-gen)
- 8–11 → 2
- 12–15 → 3
- ≥ 16 → 4

`proposeNextMatches` now accepts an optional `cap` parameter (default 4) so manual "Suggest Matches" button is unaffected. `needed = cap - existingCount`.

### Auto-backfill (`src/lib/db/proposed.ts`)
Added `backfillMatchQueue(sessionId)`: fetches checked-in count, computes cap, calls `proposeNextMatches(sessionId, cap)` if queue is below cap. Returns immediately if cap is 0 (< 8 players).

### Trigger points
- `src/app/api/sessions/[id]/checkin/route.ts` — fires `backfillMatchQueue` (fire-and-forget) after both fresh and re-check-in paths.
- `src/app/api/matches/route.ts` — fires `backfillMatchQueue` after a match is successfully recorded.
- `src/app/api/proposed-matches/[id]/route.ts` — fires `backfillMatchQueue` after a proposed match is deleted. `deleteProposedMatch` now returns the `session_id` to make this possible.

## Migration notes
No DB schema changes. No migration required.
