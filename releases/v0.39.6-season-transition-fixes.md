# v0.39.6 — Season Transition Fixes

**Released:** 2026-05-24

## Changes

### Bug fix: Spring finals showing on Summer season page
`src/app/(app)/page.tsx`

`getAllFinals()` returns finals events across all seasons. The code was finding the Spring 2026 Finals event (status `sessions_created`, i.e. not yet `completed`) and passing it to `FinalsSection` on the Summer season home page.

**Fix:** Filter `allFinalsEvents` by `activeSeason.id` before finding `finalsEvent` and `pastFinalsEvents`. Spring's finals events no longer appear when Summer is the active season.

### Bug fix: Stats tiles hidden at start of new season
`src/app/(app)/page.tsx`

The three stat cards (Players, Matches, Days of Play) were gated behind `daysOfPlay > 0`, so they disappeared entirely at the start of a new season before any sessions were completed.

**Fix:** Removed the condition — tiles always render, showing 0 values until sessions are completed.

### UX: Past Seasons expanded by default
`src/app/(app)/admin/seasons/page.tsx`

The past-seasons `<details>` element now has the `open` attribute so it's visible immediately on page load instead of requiring a click to expand.

### DB: Summer 2026 sessions seeded
Inserted 23 pending sessions (every Monday and Thursday) for the Summer 2026 season (2026-05-28 → 2026-08-13) via SQL:

```sql
INSERT INTO sessions (date, status, season_id, session_type, is_test_session)
SELECT d::date, 'pending', '059fe034-00ef-4357-ad44-08b75b00d7f2', 'regular', false
FROM generate_series('2026-05-28'::date, '2026-08-13'::date, '1 day'::interval) AS d
WHERE EXTRACT(DOW FROM d) IN (1, 4);
```
